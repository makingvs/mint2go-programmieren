# MINT2Go Programmieren

## Ziel
Eigenständige Web-App (PWA) zum Programmierenlernen für Kinder von 6–10 Jahren auf dem iPad, lehrerzentriert (Beamer-Folien, Live-Programm der Lehrkraft, danach Blöcke und Übungsaufgaben am simulierten Roboter). Statische Webseite, veröffentlicht über GitHub Pages (`npm run deploy` schiebt `dist/` auf den Zweig `gh-pages`). Herausgelöst aus dem Repository der Laser-App (dort `appcode/`).

## Technik
- HTML, CSS, TypeScript, gebaut mit Vite (Tests: Vitest); Ausgabe `dist/` = statische Webseite, Pfade relativ (base './')
- Web-App für Safari auf dem iPad, als Home-Bildschirm-App im Vollbild, nur Querformat; Touch und Maus über Pointer Events
- KEIN Server nötig: Daten auf dem Gerät (localStorage), Offline über Service Worker (`scripts/make-sw.mjs`, Cache-Präfix `app-code-`)
- Keine Laufzeit-Bibliothek (nur die Schrift Jost, OFL); Bibliotheken nur nach Rückfrage
- Gemeinsame Bausteine aus der Laser-App liegen als Kopie in `src/shared/` (dom, icons, decor, names, history)
- Befehle: `npm run dev` (Port 5175), `npm test`, `npm run build`, `npm run deploy` (Seite veröffentlichen)

## Design (MINT2Go-CD)
- Farben aus dem Logo: Grün #98C227, Orange #F0A030, Pink #E01070, Hellblau #38B8E8, Dunkelblau #3757A9, Schiefer #4D597C; Schrift Jost; Tokens in :root von `src/style.css`
- Kindgerecht: kaum Text, Symbole, Touchflächen mindestens 56 px, Größen je Fensterhöhe (@media max-height 760/640); nach Layout-Änderungen auf 900x480, 1024x768, 1366x1024 prüfen

## Programmier-App (, eigene App im selben Repo)
- Ziel: Kindern (6–10) das Programmieren Schritt für Schritt beibringen, lehrerzentriert. Teil 1 (Lehrkraft, Beamer): Einstieg "Live-Programm": die Klasse sagt mündlich die Befehle (z. B. aus einer Flasche trinken), die Lehrkraft schreibt sie als große Karten auf, dann macht ein Kind das Programm vor. Teil 2 (Kinder): blockbasiertes Programmieren mit Symbolen wie Lego Spike an einem simulierten Spike-Roboter; Konzepte: Reihenfolge, Wiederholen, Wenn-dann, Ereignisse, Variablen/Zähler (Entscheidung des Nutzers); Übungsaufgaben + freies Probieren; Unterrichtsfolge mit Folien für die Lehrkraft
- Aufbau: index.html + src/, public/ (Manifest, Icons, Logo); Build `vite.code.config.ts` -> dist/code/ mit eigenem Service Worker (`node scripts/make-sw.mjs code`, Cache-Name app-code-); `npm run dev:code` (Port 5175); `npm run build` baut alle drei Apps. Keine neue Laufzeit-Bibliothek; nutzt src/dom.ts, src/icons.ts, src/decor.ts, app3d/src/history.ts
- Reine Logik (testbar, tests/program.test.ts): program.ts (Schritte hinzufügen/einfügen/ändern/verschieben/löschen, Fehler-Markierung, Vorführ-Zustand RunState, strenges Laden parseProgram), session.ts (Rückgängig + Entwurf in localStorage `code.live`), examples.ts (6 Beispiele), stepIcons.ts (18 selbst gezeichnete Symbole)
- Oberfläche: home.ts (Startseite), liveEditor.ts (Eingabefeld OBEN, Enter = Schritt anhängen; Karte antippen = Werkzeuge: hoch/runter/ändern/Symbol/danach einfügen/Fehler/löschen; Einfügemarke), presenter.ts (Vorführen: großer aktueller Schritt, Liste mit Haken links, Gemacht/Zurück/Klappt nicht; Tasten Leertaste/Enter/Pfeile/Bild↓↑ (Fernbedienung), X = klappt nicht, Esc = bearbeiten; am Ende Konfetti)
- Fehlersuche: "Klappt nicht" markiert den Schritt rot, öffnet den Editor mit Einfügemarke DAVOR; neuer Durchlauf löscht die Markierungen. Beispiel "Flasche – mit Fehler" (es fehlt "Deckel aufdrehen")
- Blöcke (Phase 2): blocks.ts (Katalog BLOCK_DEFS: Vorwärts/Rückwärts (Schritte 1–20), Links/Rechts drehen (45–360°, Raster 45), Bild zeigen (8 Lichtmatrix-Bilder 5x5, LED_IMAGES), Licht aus, Ton (5 Töne, NOTES mit Hz), Warten (1–10 s), Wiederholen (2–20×, Container); reine Logik: insertBlock/moveBlock/removeBlock/duplicateBlock/setParam/addAtCursor, Ziele per Eltern-id + Position (null = oberste Ebene), höchstens 3 Wiederholen ineinander (MAX_NEST), 80 Blöcke (MAX_BLOCKS), strenges parseBlockProgram), blockIcons.ts (Symbole, Farben je Kategorie: Bewegung blau, Licht pink, Ton orange, Steuerung grün), blockEditor.ts (Palette links mit 4 Reitern, Programm rechts unter der Start-Flagge), blocks.css, session.ts (allgemeine Session<T> + LiveSession/BlockSession; Block-Entwurf in localStorage `code.blocks`). Bedienung: Block aus der Palette ziehen ODER antippen (kommt in den gewählten Wiederholen-Block ans Ende, sonst hinter den gewählten Block, ohne Auswahl ans Ende); vorhandene Blöcke am Griff links ziehen; auf die Palette ziehen = löschen (Rückfrage nur bei Wiederholen mit Inhalt); Block antippen = Kopieren/Löschen; Zahl/Bild/Ton antippen = Fenster (Plus/Minus bzw. Auswahl); Esc bricht Ziehen ab; Rand der Fläche beim Ziehen scrollt. Die Einfügestellen sind `.slot`-Elemente, die nächste zum Finger (< 70 px) leuchtet orange. Die Blöcke werden erst in Phase 3 ausgeführt (noch keine Start-Taste)
- Roboter (Phase 3): sim.ts (reine Logik: World 12x8 Felder, Start (1,5|6,5) schaut nach oben; compile = Block-Programm -> Anweisungen mit Block-id, Wiederholen wird ausgerollt mit Marke je Durchlauf, höchstens 2000; apply(Zustand, Anweisung, Welt, t) = Zustand nach Bruchteil t, Heading 0 = oben, rechts = im Uhrzeigersinn, Wand stoppt den Roboter (WALL_MARGIN 0,5) und meldet bumped; durationFor; simulate() = ganzes Programm sofort, auch für die spätere Aufgaben-Prüfung), simPlayer.ts (SimPlayer mit austauschbarer Uhr: play/step/stop/setSpeed, Modi idle/playing/stepping/done; Programm wird beim Start festgehalten), stagePanel.ts (rechte Spalte: Boden als SVG mit Spur und Roboter samt Lichtmatrix, Display wie am Spike-Hub, Tasten Start/Stopp/Schritt/Tempo (1x/2,5x)/Ton), audio.ts (Web Audio: Ton je Note, tiefer Stoß-Ton; `unlockAudio()` im Tipp; Ton an/aus in localStorage `code.sound`). Im Editor leuchtet der laufende Block, bei Wiederholen steht "Durchlauf/Anzahl"; jede Änderung am Programm (auch Rückgängig) setzt den Roboter zurück. Aufgaben mit Zielen/Hindernissen (Phase 5) hängen sich über World an
- Bedingungen, Ereignisse, Zähler (Phase 4): blocks.ts hat 6 Kategorien (Bewegung, Licht, Ton, Steuerung, Ereignisse, Zähler; Palette = 3x2 Reiter, Liste wischt senkrecht, Ziehen nach rechts). Neue Blöcke: Wiederhole bis (Bedingung), Immer, Wenn (Bedingung), Wenn Zähler (<, =, > Zahl), Zähler setzen (-99..99), Zähler ändern (-9..9); Bedingungen CONDITIONS = Wand vor mir (kein ganzer Schritt mehr frei) / Weg frei; nur EIN Zähler (RobotState.count, wird auf der Bühne oben rechts angezeigt, sobald das Programm ihn benutzt). Ereignis-Skripte: BlockProgram.events {tap, bump} neben dem Hauptprogramm (Köpfe "Wenn getippt" = Roboter oder Display antippen, "Wenn Wand berührt"); jedes höchstens einmal; Eltern-ids HAT_PARENT (tap -1, bump -2, Hauptprogramm null), so gelten alle Listen-Operationen (insert/move/…) auch für sie; Köpfe aus der Palette tippen oder auf die Fläche ziehen, Skript mit × am Kopf löschen. Ablauf: machine.ts (Thread = Interpreter mit Rahmen für Wiederholen/Bedingungen, wertet Bedingungen erst aus, wenn sie dran sind; Machine = Hauptprogramm + Ereignis-Skripte, `next()/complete()/fire()`, MAX_INSTRS 3000 gegen Endlosschleifen, `simulate()` = sofort ausführen; `compile` gibt es nicht mehr). Ein Ereignis unterbricht das Hauptprogramm zwischen zwei Anweisungen (Skript läuft zu Ende, derselbe Kopf nicht verschachtelt); hat das Programm Ereignis-Skripte, wartet es nach dem Ende im Modus `listening` ("Wartet", blauer Rahmen) bis Stopp. Jede Prüfung (Wenn, Wiederhole bis) ist eine Anweisung mit Ergebnis: am Block erscheint grüner Haken/graues Kreuz (`data-check`)
- Aufgaben (Phase 5): tasks.ts (reine Logik: 15 Aufgaben in 4 Stufen LEVELS = Reihenfolge, Wiederholen, Wenn und Bis, Zähler und Ereignisse; Karte als 12x8 Zeichen: `#` Hindernis, `S` Start, `G` Ziel, `X` Start+Ziel, `*` Stern; `allowed` = Blöcke in der Palette (nur diese, leere Reiter verschwinden), `maxBlocks`, `use` (Pflichtblöcke, whenTap/whenBump = Ereignis-Skript), `does` (mindestens n ausgeführte Anweisungen einer Art), `image`, `count`, `fire` (Ereignis wird bei der Prüfung ausgelöst); `checkTask(task, program)` führt simulate() aus und liefert je Bedingung ok/nicht ok, `requirements()` = was verlangt wird, `parseDone`). Welt hat `obstacles` (Feldliste): der Roboter ist ein Kreis mit Radius 0,5 und stoppt vor Hindernissen genau in der Feldmitte (sim.ts sweep/blockedAt, meldet Stoß wie die Wand), "Wand vor mir" erkennt Hindernisse mit; `visited(state, cell)` = Weg kommt der Feldmitte näher als 0,35 (Sterne), `inCell` (Ziel). Oberfläche: taskScreen.ts (Auswahl nach Stufen mit Karten-Vorschau und Haken), taskUi.ts (Karten-Vorschau, Bedingungs-Symbole `req-chip` mit Zustand todo/ok/no, Fenster "Aufgabe" beim Öffnen und über die Taste Aufgabe, Fenster "Geschafft" mit Konfetti: Aufgaben/Ändern/Weiter), scene.ts (Hindernis-, Ziel-, Sternzeichnung), tasks.css. Editor im Aufgabenmodus (blockScreen mit `task`): Welt der Aufgabe, Bedingungen als Symbole in der Kopfleiste, Prüfung 600 ms nach Ende des Laufs (bei "Wenn getippt" erst nach dem echten Antippen, 900 ms), jede Änderung am Programm setzt die Symbole zurück; Sterne verschwinden beim Überfahren. Speicher: je Aufgabe ein eigenes Programm `code.task.<id>` (TaskSession), gelöste Aufgaben `code.tasks.done` (nur auf diesem Gerät). Neu im Editor: Ereignis-Kopf antippen wählt das Skript, neue Blöcke aus der Palette kommen hinein (ein neu angelegter Kopf ist gleich gewählt)
- Unterricht (Phase 6): lesson.ts (reine Daten: 4 Lektionen à 5–6 Folien, je ca. 45 Minuten: Befehle und Reihenfolge, Wiederholen, Wenn und Bis, Ereignisse und Zähler; Folie = Titel, kurzer Text (< 150 Zeichen, Beamer), optional Merksatz `keep`, Beispiel aus Blöcken `visual` (nur Anzeige, VisualBlock mit Kindern), Sprungtaste `action` (live/blocks/tasks/task:<id>) und Notizen für die Lehrkraft), lessonScreen.ts (Lektionsliste und Folien-Ansicht: Tasten Leertaste/Enter/Pfeile/Bild↓↑ = weiter/zurück, N = Notizen, Esc = Liste; Punkte zeigen den Stand), lesson.css. Sprungtasten öffnen Live-Programm, Blöcke, Aufgabenliste oder eine Aufgabe; "Start" in der App bringt zurück zur Folie (main.ts `returnTo`/`goHome`). Startseite hat jetzt 4 Karten (Unterricht, Einstieg, Blöcke, Aufgaben). Folien-Inhalt ändern = nur lesson.ts; tests/lesson.test.ts prüft Verweise auf Aufgaben, Blöcke und Werte
- Profile/Speichern (Phase 7): profiles.ts (reine Regeln: Kind = Name + Tier-Symbol aus ANIMALS der Laser-App, Name höchstens 20 Zeichen und eindeutig, Symbol je Kind eigenes und erst mit dem Löschen wieder frei, höchstens 40 Kinder; Schlüssel `code.p.<id>.blocks|task.<taskId>|done`), store.ts (KV = localStorage mit try/catch, memoryKV für Tests), profileStore.ts (Kinderliste, aktuelles Kind `code.profile`, gelöste Aufgaben, resetProgress, deleteProfile, classOverview), session.ts (TaskSession(profileId, taskId), BlockSession(profileId); Live-Programm `code.live` gehört der Lehrkraft/dem Gerät). Oberfläche: Startseite mit Kind-Marke (antippen = wechseln); Blöcke und Aufgaben fragen zuerst "Wer bist du?" (profileScreen.ts, Neu-Fenster mit Eingabefeld oben, Gerätetastatur), Aufgabenliste zeigt das Kind und den Fortschritt dieses Kindes; Lehrkraft-Bereich = langer Druck (1,5 s) auf das Logo der Startseite -> teacherScreen.ts (Klassenübersicht: Zeile je Kind, Spalte je Aufgabe in der Stufenfarbe, Summe, Fußzeile = wie viele Kinder die Aufgabe gelöst haben; Fortschritt zurücksetzen und Kind löschen je mit Rückfrage), profile.css. Alle Daten bleiben auf dem Gerät (kein Server, kein Export)
- Phasen Programmieren: 1 Gerüst + Live-Programm (fertig) · 2 Blöcke-Editor (fertig) · 3 Spike-Roboter-Simulator + Ausführen (fertig) · 4 Wenn-dann, Ereignisse, Variablen (fertig) · 5 Übungsaufgaben mit automatischer Prüfung (fertig) · 6 Unterrichtsfolge/Folien für die Lehrkraft (fertig) · 7 Profile/Speichern/Klassentest (fertig)
